STEP 1: Input Message Plaintext & Pad Bits

BLAKE3 processes messages in 1024-byte chunks divided into 64-byte blocks. Unaligned blocks are zero-padded up to 64 bytes without appending length fields.

Why do we pad the message plaintext?

512-bit (64-byte) Block Alignment: BLAKE3 compression function operates on 16 32-bit words.
Padding Structure: Zero-pads trailing blocks up to 64 bytes. Domain separation flags (CHUNK_START, CHUNK_END, ROOT) handle length distinction rather than padded length bits.
This enables parallel tree hashing and extreme performance.

STEP 2: Prepare Message Schedule (W0 to W63)

Extract 16 words (32 bits each) from the message block and apply BLAKE3's fixed index permutation matrix across rounds.

How are words expanded from plaintext?

The first 16 words m[0..15] are drawn directly from the 64-byte message block.
Subsequent round schedules index m[...] via array permutation: MSG_SCHEDULE[round][i].
Permutation pattern: 2, 6, 3, 10, 7, 0, 4, 13, 1, 11, 12, 5, 9, 14, 15, 8.
